# Adding a contract function

One new contract function touches several places in the repo. This guide uses
the governance `cancel(caller, proposal_id)` function to show each one. Update
every row that applies, in the same PR, and run the check listed next to it.

## Checklist

| # | File | What to change | Check that enforces it |
|---|------|----------------|------------------------|
| 1 | `contracts/governance/src/lib.rs` (or `contracts/token/src/lib.rs`) | The function inside `#[contractimpl]`: `require_auth()` on the caller, a `Result<_, GovernanceError>` return, checked arithmetic, and an `env.events().publish(...)` for the state change. `cancel` publishes `("proposal_cancelled", id)` with a `ProposalCancelled { id, caller }` struct. | `cargo build`, `cargo clippy -- -D warnings` (CI `contracts` job) |
| 2 | `contracts/governance/src/test.rs` | A happy-path test, an error-path test, and a test that asserts the event, e.g. `cancelling_emits_proposal_cancelled_with_the_caller`. | `cargo test` (CI `contracts` job) |
| 3 | New error variant, if any, in the contract's error enum | Append it with the next free code. Never renumber. | — |
| 4 | `sdk/src/errors.ts` | Mirror any new error variant with the same name and code. | `sdk/test/errors.test.ts` compares the TS enums to the Rust enums |
| 5 | `sdk/src/events.ts` | Add the topic to `EVENT_TOPICS`, an event interface, the `QuorumEvent` union and a `decodeEvent` case. Export the interface from `sdk/src/index.ts`. | `sdk/test/events.test.ts` fails if a Rust `Symbol::new(&env, "…")` topic is missing from `EVENT_TOPICS`, or if a topic has no decode sample |
| 6 | `sdk/test/events.test.ts` | Add a decode sample for the new topic. | Same test as row 5 |
| 7 | `sdk/src/client.ts` | A `QuorumClient` method: a read via simulation, or a `build…` method that returns signable XDR, as `buildCancel` does. To leave a function unwrapped on purpose, add it to `EXCLUSIONS` in `sdk/scripts/check-wrapper-coverage.mjs` with a reason. | `sdk/scripts/check-wrapper-coverage.mjs` |
| 8 | `sdk/spec/quorum-client.spec.json` | Regenerate with `cd sdk && npm run spec`. Never edit it by hand. | `npm run spec:check` (CI `sdk` job) |
| 9 | `README.md`, section `## SDK Reference` | Show the new client method if users call it directly. | `npm run spec:check` fails if the README calls a method the client lacks |
| 10 | `contracts/governance/README.md`, section `## Function Reference` | A `### name` entry with the signature, parameters, errors and **Events:** line. | Review |
| 11 | `docs/architecture.md`, events table | A row for each new event topic. | Review |
| 12 | `sdk/README.md` | Add new event topics to the decoder coverage list. | Review |
| 13 | `sdk/python/src/quorum_sdk/` | Only for **read-only** functions: a method on `QuorumClient` in `client.py`, plus models in `models.py` if needed, and shared XDR fixtures under `sdk/test/fixtures/`. | `pytest sdk/python/tests` (CI `sdk-python` job) and `sdk/test/python-parity.test.ts` |
| 14 | `frontend/` | Only if the UI calls the function. Call it through the SDK client, never with raw XDR, and add any user-facing strings to `frontend/messages/en.json`. | `npm run lint`, `npm test` and `npm run build` (CI `frontend` job) |
| 15 | `CHANGELOG.md` / `sdk/CHANGELOG.md` | An entry under the unreleased section. | Review |

## Order that keeps CI green

1. Contract code and tests (rows 1–3). Run `cd contracts && cargo test`.
2. SDK mirrors (rows 4–8). Run `cd sdk && npm test && npm run spec:check`.
3. Docs (rows 9–12 and 15).
4. Python and frontend, only where they apply (rows 13–14).

Contract specs for released WASM are generated by `.github/workflows/contract-specs.yml`.
Nothing in this checklist needs to be edited for that workflow.
